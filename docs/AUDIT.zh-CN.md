# learn-any-skill v0.2.0 检查与完善报告

检查日期：2026-09-21。基于实际收到的原始 ZIP 全部源码，先读取原文件、复现脚本边界问题，再修改和测试。原始压缩包被保留，新版本单独输出，没有替你创建或修改远程 GitHub 仓库。

## 总体判断

原版的“能力目标 → 搜索 → 筛选 → 项目 → 验收”方向成立，不需要推倒重来。但更接近课程路线生成器：对于逐课正文、持续授课、进度恢复、证据记录、脚本边界和发布检查，仍缺少具体机制。新版补充这些内容，同时明确它是宿主驱动的 Skill，而不是已经实现的自动化学习平台。

## 主要问题与修改

| 项目 | 原版问题或缺口 | v0.2.0 处理 |
|---|---|---|
| 完整课程 | 有课程路线，但没有完整逐课课卡和原创讲解的交付规范 | 增加 build/teach 等意图、课卡模板和三节完整样例 |
| 搜索证据 | 提到核验，缺少可追溯的结构化状态 | 加入 content-verified / metadata-only / unverified / local、检查日期、章节、证据与限制 |
| 搜索范围 | 缺少具体的搜索停止条件和资源上限处理 | 按能力缺口搜索，覆盖足够即停止；不可覆盖时明确缺口 |
| 筛选与预算 | 有评分原则，但缺少课程依赖和学时自动检查 | 添加 validate_plan.py，检查引用、依赖环、顺序、覆盖和含缓冲的总学时 |
| 评分类型 | 布尔值被当作数值接受 | 明确拒绝 bool，保留正常数字 |
| 非有限权重 | Infinity 权重可导致输出 NaN | 拒绝非有限值；大但有限的权重先缩放再归一化 |
| 错误容器 | 空数组 weights 被静默接受 | 只接受对象；空对象用默认值，数组/null/bool 均拒绝 |
| 空输入 | 空资源列表输出空表，未报错 | 空输入明确报错并返回非零退出码 |
| 排序与输出 | 按四舍五入后的分数排序，Markdown 单元格处理不完整 | 按未舍入分数排，处理换行、竖线和 HTML；保留 ledger/fixture 元数据 |
| 进度 | 缺少真实证据、状态定义和恢复流程 | 加入 progress 模板/Schema；没有学习证据不能声称通过 |
| 工具与安全 | 没有细分无网络、无文件、无执行工具的处理 | 增加降级、权限、提示注入、隐私和版权边界 |
| 安装与发布 | 用户级示例使用旧目录；缺少中文 Windows 发布步骤 | 依据官方文档改用 .agents/skills；补齐中文说明、发布教程、CI 和问题模板 |
| 质量保证 | 原 CI 主要是文件存在性和单个示例运行 | 新增本地回归测试、Schema 校验、完整实验和人工行为评测清单 |

## 原脚本实际复现结果

以下是在修改前运行原脚本函数获得的结果，而不是假设：

```text
boolean score       → ACCEPTED，输出了分数
infinite weight     → ACCEPTED，输出 [nan, nan, nan]
weights = []        → ACCEPTED，退回默认权重
resources = []      → ACCEPTED，得到空结果
```

新版针对这些情况均有回归测试。对合法旧样例仍保持 90.0、89.0、68.0 的排序和分数；这些是人为构造的算术测试输入，并非真实课程排名。原来的 GitHub 示例占位链接改为明确标记的 example.com 测试地址，避免被误认为真实项目推荐。

## 必须保留的限制说明

**尚未执行**真实 Codex/其他宿主里的端到端授课或隐式触发测试；`evals/` 是待实际运行的人工行为评测清单，不是已经得到成绩的模型评测。GitHub Actions 的 Linux/Windows、多 Python 版本矩阵已经配置，但远程运行结果需要发布后观察。本地只实际运行了上面列出的 Python 环境。

没有测量“学习快了多少”“课程质量优于其他方案”或长期学习效果，也没有证明“全网最短/最优课程”。评分维度由模型或人依据证据判断，脚本只保证相关计算；课程校验器只检查**声明**的证据、依赖和预算，不能独立判断网上内容是否真实。

六种模式是 Skill 指令和模板中的工作流程，不是注册好的 CLI/斜杠命令，更不是自动后台服务。需要搜索、阅读、执行和保存时，由宿主提供对应能力和授权。

建议将本包作为 **v0.2.0 的开源初版迭代**发布，而不是宣传为经过大规模用户验证的生产学习平台。先按 [发布教程](PUBLISH.zh-CN.md) 上传源码并查看实际 CI 结果，再用一个 RAG 或 Agent 学习任务做真实宿主试用，记录失败案例继续迭代。
